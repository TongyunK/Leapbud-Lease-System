## 1. 合約：起止日期與合約期表格

### 1.1 用戶填寫的合約總日期

- **合約開始日期**、**合約到期日期**由用戶在表單上方填寫，**不是**由合約期自動彙總推導唯一真相。
- 校驗規則：
  - 第一段合約期的開始日 = 合約開始日
  - 最後一段合約期的結束日 = 合約到期日
  - 各段起止合法、段間不可重疊

### 1.2 雙向聯動（總日期 ↔ 合約期）

| 方向 | 行為 |
|------|------|
| 合約開始日變更 | 寫入第一段開始日；若已有結束日則反推時長，否則按單位/數值推結束日，並向後串聯後續段 |
| 合約到期日變更 | 寫入最後一段結束日，並反推該段時長 |
| 合約期首段開始 / 末段結束變更（含改數值串聯後） | **回寫**上方合約開始 / 到期日 |

實現要點：用「誰改誰驅動」+ 同步鎖（必要時 `nextTick` 放鎖），避免同一次改動裡兩邊互相覆蓋。

### 1.3 合約期表格：日期 ↔ 單位 / 數值

| 用戶操作 | 自動結果 |
|----------|----------|
| 填齊開始 + 結束日 | 反推單位（月優先，否則日）與數值 |
| 改單位或數值 | 在已有開始日下推算結束日（月：開始 + N 月 − 1 天；日：開始 + N − 1 天） |
| 缺開始日時改單位/數值 | 首段用合約開始日；其後段用上一段結束日 + 1，再推結束日 |

**注意**

- 整月含月末鉗制（如 1/31），正算與反推偶發不完全對稱，屬預期。
- 預設新建行常為「12 月」；僅填合約開始日時，可能據此自動帶出結束日並回寫總到期日。

### 1.4 多段合約期前向串聯

任意修改某一段的結束日 / 單位 / 數值後：

1. 下一段開始日 = 上一段結束日 + 1
2. 下一段按自身單位/數值重算結束日
3. 依次向後傳遞；末段結束日再與合約總到期日雙向對齊

刪除中間段、拖拽或雙擊序號調序後：從首段起按「合約開始 + 各段時長」重串日期鏈。

### 1.5 合約期表格交互約定（表單內嵌）

- 每頁最多 5 條；超過顯示分頁
- 支援拖拽排序、雙擊序號跨頁改位置
- 提交按當前數組順序寫 `sortOrder`（0-based）

### 1.6 列表頁頭快捷篩選

- **全部／整租／分租**：三選一，用來按租賃方式篩選列表（芯片上帶數量）。
- **即將到期**：可與整租／分租**同時選中**；芯片顯示符合條件的合約數量。
  - 什麼算「即將到期」（可由 **SuperAdmin** 調整）：
    - 合約到期日落在「今天起算、往後一段時間」之內（預設 **30 天**）
    - 可限定或排除合約狀態（預設只含「租賃中」「退租中」）
  - **誰能改條件**：僅 SuperAdmin。在「即將到期」芯片旁有鉛筆圖標（滑鼠移上去才較明顯），點開後可改天數／月數與狀態條件；改完立即影響數量與列表。一般管理員請到合約列表使用，**不必**進系統設置頁。
  - 數量只統計當前可看的大廈範圍；與是否勾選整租／分租無關。
  - 再點一次芯片可取消；點「清空篩選」時也會一併關閉。

### 1.7 列表操作列

主列常駐：**編輯**、**收款**、**列印**、**…（更多）**。其餘操作收在「更多」面板中，並按用途分組：

| 分組 | 操作 | 說明 |
|------|------|------|
| 主列 | 收款 | 打開「合約收款」：列出該合約全部應收與未收合計；勾選後確認收款日期／方式，為每筆未收應收開立收據（需 `receipts:create`）；收據金額合計會回寫應收已收／未收 |
| 辦理 | 開單、續約 | 開單：僅簽約中可上傳簽約文件後變為租賃中，其他狀態提示不可執行；續約：功能開發中 |
| 記錄 | 發票記錄 | 查看本合約關聯發票（尚無發票時也可打開，顯示空列表） |
| 結束 | 退租、取消、刪除 | 退租：功能開發中；取消：僅「簽約中」；刪除：需具備刪除權限，確認後刪除該合約 |

- 打開「更多」時，面板**頂部會顯示當前合約編號**，方便核對是否點錯行。
- 從「更多」執行操作時：若彈出 **MessageBox**（狀態不可用提示、取消／刪除確認等），**不會自動關閉**更多面板；僅在進入下一界面（如開單上傳彈窗、發票抽屜）或操作成功後才關閉。MessageBox 層級高於更多面板，點遮罩確認時也不會誤關面板。

## 2. 合約：免租期與首張租金發票

### 2.1 合約期類型

配置字典 `periodType`（示例）：

| code | 標籤 |
|------|------|
| `usage` | 使用期 |
| `mandatory` | 必須使用期 |
| `rent_free` | 免租期 |

判斷免租：配置 `code === rent_free`，或標籤為「免租期」/ 含「免租」。

### 2.2 禁止「僅有免租期」

- **不可**提交僅含免租期的合約（含「只有一條免租期」、或全部段落皆免租）。
- 必須至少有一段**非免租**（使用期或必須使用期）。
- 前後端均校驗：
  - 前端：合約表單提交
  - 後端：合約 create/update；合約期模組 create/update/remove（避免改到「只剩免租」）

文案鍵：`contract.periodNeedUsage`

### 2.3 租金繳費起算日（有前綴免租時）

當合約從**開始日連續**存在免租期時：

- 租金**繳費切片起算日** = 最後一段前綴免租的結束日 **+ 1 天**
- **第一張「繳費期 / Charging Period」租金發票**從該日起算，而不是合約總開始日
- 日任務提前開下期租金發票，同樣使用此起算日

無前綴免租（首段即使用期）時：起算日 = 合約開始日（與舊行為一致）。

中間插入的免租段：不改變「第一張」從合約開始起算的規則；前綴連續免租才會後移首期。

實現：`backend/src/common/billing-period.ts` → `rentBillingStartDate`；`InvoiceAutoService.ensureFirstRentInvoice` / `runDueRentInvoices`

## 3. 合約：直接開單與自動開票

### 3.1 創建 / 保存即生成首期票據

合約**新增或保存**（含仍為「簽約中」）時，事務內**冪等**生成：

1. **房間按金發票**（`billingKind=auto`，`invoiceType=Deposit`）  
   - 明細含：房間按金、雜項按金（若有）、**房門匙或信箱匙**（合併一條）、借出用品等  
2. **首個繳費週期租金發票**（`billingKind=auto`，`invoiceType=1, Charging Period`，受 §2.3 免租起算約束）  
3. 各發票對應的**應收帳**

實現：`InvoiceAutoService.ensureInitialInvoicesOnIssue`（創建 / 更新 / 開單路徑均調用）。

### 3.2 開單（簽約文件 → 租賃中）

| 入口 | 行為 |
|------|------|
| 列表「開單」`openOrder` | 上傳租客簽約文件；僅「簽約中」；狀態 → **租賃中**。非簽約中點擊時以 **MessageBox** 提示「當前狀態不可執行該操作」；若從「更多」面板觸發則面板保持打開（見 §1.7） |
| 表單「直接開單」`issueNow` | 同上 + 保存；須已填附件 |

開單時另生成**定金收據**（`ensureBookingDepositReceipt`）。  
按金 / 首期發票若創建時已有，開單再調用仍冪等，不重複開。

**開單前（簽約中）不會**由日任務自動開立第 2 個及以後繳費期的租金發票。

### 3.3 後續租金發票（排程）

- 日任務**僅處理狀態 = 租賃中**的合約  
- 距某繳費週期開始 ≤ **N** 日且尚未開票 → 自動開該期租金發票 + 應收  
- **N** 取自系統設置「繳費期前自動開票天數」（詳見 [§6](#6-系統設置)，預設 7）  
- 切片依據：`paymentCycle` 與 `[繳費起算日, 合約到期日]`  
- 若合約仍為**簽約中**且已進入第 2 期提前窗：  
  - **不開票**  
  - 後端日任務記 warn 日誌  
  - 前端：頁頭「待開單 N」芯片為**當前大厦範圍內全量**緊急項（`GET /contracts/alerts/issue-blocked`，不受列表分頁限制；按第 2 期開始日緊急程度排序）；點編號開詳情、右側「開單」快捷處理；另有狀態列警示圖標 + 編輯表單內提示

### 3.4 暫未做

- 開票後 WhatsApp / Email 通知（延後）

## 4. 財務：發票編輯與刪除

### 4.1 發票手工編輯（列表）

入口：**財務管理 → 發票**操作列「編輯」（需 `invoices:update`）。

| 項目 | 規則 |
|------|------|
| 回填 | 打開時 `GET /invoices/:id` 拉全量（含服務細節），避免列表緩存缺行 |
| 合約 | 編輯時合約下拉**禁用**（不可改所屬合約）；客戶／房間只讀帶出 |
| 可改字段 | 類型（Deposit／Others／1, Charging Period）、金額、發票日／收款期限、備註、服務細節行 |
| 必填 | 合約、**發票日期**、**收款期限**（保存前前端校驗） |
| 發票編號 | 表單置於合約編號左側；**新增**只讀預覽下一號（`GET /invoices/code-preview`，選合約後帶房間后缀）；保存時重新分配不占用預覽序號；**編輯**只讀原號 |
| 新增默認 | 類型＝**Others**；銷售經理**表單隱藏**，自動跟隨合約（合約無則回退當前登錄用戶）；發票日期＝今日；開票金額＝0.00；狀態固定**已開票**（表單不展示狀態） |
| 來源 | `source=contract`（列表徽章「合約」）；與短租發票見 §5 |
| 產生方式 | `billingKind` 僅兩值：`manual`＝用戶手動、`auto`＝系統自動；按金／租金等由 `invoiceType` 區分。手工新增一律 `manual`；列表可篩選 |
| 表單不再編輯 | **發票描述**（列表／表單／詳情均隱藏；庫字段保留；新增合約票後端寫入英文類型作列印無明細回退；系統自動租金票仍寫週期文案；編輯不改）；房間名稱文本、WhatsApp、短租編號、應收帳引用、開票附件、notes；`billingKind` 只讀 |
| 服務細節表 | 與合約期一致：每頁最多 5 行、拖拽排序、雙擊序號可跨頁改位；提交按當前數組順序寫 `sortOrder` |
| 預覽 | 彈窗底部「預覽」：按**當前表單**（含未保存）生成 PDF（`POST .../prints/invoice/preview-ticket` + `draft`；新增可無 `invoiceId`）；須已選合約（或短租客戶／房間）及發票日／收款期限 |
| 保存 | `PATCH /invoices/:id`；服務細節整表替換（傳入數組） |

操作列配色與合約對齊：列印=`--leave`（霧紫）、編輯=`--edit`（綠）、刪除=`--danger`（紅）。全站其它表亦按同一語義（見 `style.css` `.action-pill--*` 注釋）。

### 4.2 刪除權限

- 單刪：`invoices:delete` / `receivables:delete` / `receipts:delete`
- 批量：對應 `*:batchDelete`
- 普通角色預設**不含**刪除權；需在角色管理勾選。僅超級管理員默認全開；管理員須另行授權（規則見 §9）。

### 4.3 刪除行為與關聯

| 對象 | 行為 |
|------|------|
| 發票 | 事務內先刪**下屬應收**，再刪發票；服務細節 Cascade；收據上的 `invoiceId` SetNull |
| 應收 | 可直接刪；收據上的 `receivableId` SetNull |
| 收據 | 刪庫 + 清理附件檔；合約定金指針 SetNull |

### 4.4 注意

- 有應收的發票以前會因 Restrict 刪失敗；現已級聯刪應收。刪發票會一併去掉對應應收，需業務上確認可接受。
- 刪除後若從**關聯抽屜**操作，主列表應刷新（見 §6.3）。
- 關聯衝突（FK）時返回可讀中文錯誤，避免裸 Prisma 500。

## 5. 財務：短租發票（無合約）

**不做**獨立「短租單」實體；短租 = 一張 `source=short_term` 的發票本身（一次性交易）。

### 5.1 房間開關

- 房間字段 `allowShortTerm`（允許短租），默認關；僅開啟的房間可選入短租開票。
- 入口：房間新增／編輯表單開關（需 `rooms:update`）。

### 5.2 開票入口與字段

入口：**財務管理 → 發票**「新增發票」打開統一彈窗，頂部以**分段按鈕**切換「合約發票／短租發票」（需 `invoices:create`）；編輯時不顯示切換。

| 項目 | 規則 |
|------|------|
| 來源 | `source=short_term`；`contractId` 為空 |
| 必填 | 客戶、房間（須 `allowShortTerm`）、租賃起止日、發票日期、收款期限 |
| 可選 | 經此客戶介紹、描述租賃時長、金額（默認 0.00）、服務細節、備註 |
| 只讀帶出 | 房間信息、房間呎吋（選房後） |
| 編號 | 沿用發票自動編號 + 房間后缀；同時寫入 `shortTermRentalCode`（默認同發票號） |
| 發票類型 | 短租固定 **會議室短租**；合約票三選一（存英文）：**Deposit**／**Others**（手工新增默認）／**1, Charging Period**，界面中英展示 |
| 默認狀態 | 新增固定**已開票** |
| 銷售經理 | 表單隱藏，默認當前登錄用戶 |

### 5.3 占用「短租中」

- 有效短租發票：`source=short_term` 且狀態 ≠ 已取消，且**今天**落在 `[rentalStartDate, rentalEndDate]`。
- 房間占用：`occupancy.summary = short`（狀態列／篩選：**短租中**）；合約占用優先於短租展示。
- 衝突：短租保存時房間不得有占用中合約，且租期不得與其它有效短租重疊；簽約占用時若存在未結束短租租期則拒絕。

### 5.4 下游

- 應收 `contractId` 可空（短租應收掛發票／客戶／房間）。
- 收據合約本即可空，跟發票即可。

## 6. 關聯列表抽屜：多選與工具列操作

適用：`RelatedInvoicesDrawer` / `RelatedReceivablesDrawer` / `RelatedReceiptsDrawer`（合約、客戶、房間、發票、應收、按金退還等入口）。

### 6.1 工具列（無行內操作列）

搜索框右側放置操作按鈕；**不**再使用表格「操作」列。

| 按鈕 | 發票 | 應收 | 收據 |
|------|------|------|------|
| 列印 | ✓ | —（不可列印） | ✓ |
| 刪除 | ✓（需權限） | ✓（需權限） | ✓（需權限） |

### 6.2 多選與可否批量

- **有操作按鈕**的抽屜：顯示多選框 + 底部分頁「全選當前篩選」。
- **暫無操作按鈕**的關聯抽屜（如合約期、其他費用）：**不**顯示多選框。
- 應收：無刪除權限時不顯示多選與刪除鈕。

| 操作 | 規則 |
|------|------|
| 刪除 | 可批量；未勾選 → 提示先勾選；確認後批量刪 |
| 列印 | **僅單筆**；未選 → 提示先勾選；多選 → 提示「列印僅支援單筆」 |

### 6.3 刪除後主表刷新

關聯抽屜刪除成功後發出 `changed`；各主列表頁監聽並 `loadList`（收據頁同時刷新 kind 芯片計數）。  
經 `RelatedEntityDrawers` 打開的內嵌關聯列表同樣向上冒泡 `changed`。

## 7. 系統設置

入口：**系統管理 → 系統設置**（路由 `system/settings`，菜單 `menu_system_settings`）。

### 7.1 用途與頁面結構

- 存放**系統級可配置參數**（鍵值表 `system_settings`），供排程 / 業務模組讀取，避免硬編碼。
- 頁面採用「**左側分類導航 + 右側設置卡片**」：
  - 左欄按業務域分組（當前：自動開票）
  - 右欄每張卡片內用「說明在左、控件在右」的設置行；可多行擴展
  - 底部粘性操作欄：最近更新人/時間、未儲存提示、還原、儲存
- 普通 `user` 角色**無**此菜單（admin / superAdmin 可見）
- 寫入權限：開票參數需 `systemSettings:update`
- 「即將到期」條件**不在本頁**調整：請到合約列表，由 SuperAdmin 在芯片旁修改

### 7.2 當前參數

| 參數鍵 | 表單字段 | 含義 | 範圍 | 預設 |
|--------|----------|------|------|------|
| `rent_invoice_lead_days` | `rentInvoiceLeadDays` | 距下一繳費週期開始日還有多少天時自動開租金發票（**含當天**） | 整數 1–90 | **7** |
| `contract_expiring_soon` | `contractExpiringSoon`（JSON：`amount` / `unit` / `statusMode` / `statuses`） | 合約列表「即將到期」：到期日前多久 + 狀態含/排 | `unit=day` 時 amount 1–365；`month` 時 1–36；`statusMode`=`all`\|`include`\|`exclude` | **30 天**、**僅含**「租賃中」「退租中」 |

讀取方：

- 開票提前天數：`InvoiceAutoService.runDueRentInvoices`
- 即將到期：`ContractsService.countExpiringSoon` / 列表 `expiringSoon=1`

### 7.3 API

| 方法 | 路徑 | 權限 | 說明 |
|------|------|------|------|
| `GET` | `/system-settings` | 登入用戶（有菜單即可） | 回傳當前參數視圖（含 `contractExpiringSoon`、`updatedAt` / `updatedBy`） |
| `PUT` | `/system-settings` | `systemSettings:update` | 更新開票等通用字段 |
| `PUT` | `/system-settings/contract-expiring-soon` | **僅 SuperAdmin** | 更新即將到期篩選條件（入口在合約列表芯片） |

### 7.4 擴展約定（新增參數時）

1. Prisma `SystemSetting`：migration 插入默認行 + `COMMENT ON`；`seed` upsert 同鍵  
2. 後端：`system-settings.constants` / DTO / `SystemSettingsService.getView`+`update`（或獨立 update）；業務側用 `getXxx()` 讀取，**禁止**再寫死魔術數字  
3. 前端：`SystemSettingsView` 在對應分類卡片加設置行；必要時新增左欄分類；i18n（`zh-TW` / `en`）同步  
4. **同步更新本文 §6.2 與 §9 總表**

參考：`SystemSettingsView.vue`、`backend/src/system-settings/*`、`permission.catalog` → `systemSettings`

## 8. 定時任務

入口：**系統管理 → 定時任務**（路由 `system/scheduled-jobs`，菜單 `menu_scheduled_jobs`）。

### 8.1 用途與約束

- 系統預置任務註冊表（`scheduled_jobs`），**不可刪除**；可**開關**、**手動運行**、**調整名稱 / 執行時刻 / 重複週期**。
- 列表一次展示全部預置任務（一次性任務模型預留）；**無創建人列**（預置任務通常無創建人，避免只顯示時間戳）。
- 編輯彈窗中「執行功能」為**只讀展示**（代碼註冊的 handler，不可改選）。
- 關閉後**不自動跑**，仍可手動運行。
- 寫入／手動運行需 `scheduledJobs:update`；普通 `user` 角色默認無此菜單。功能按鈕是否可見取決於該角色是否被授予對應權限（見 §9），**不再**假設管理員默認全開。

### 8.2 當前預置任務

| 編碼 | 處理器 | 默認時刻 (HK) | 說明 |
|------|--------|---------------|------|
| `rent_invoice_due` | `rent_invoice_due` | `01:00`（每天） | 調用 `InvoiceAutoService.runDueRentInvoices`；提前天數讀系統設置 `rent_invoice_lead_days` |

### 8.3 重複週期（`recurrence` + `recurrence_config`）

| recurrence | 含義 | recurrence_config |
|------------|------|-------------------|
| `daily` | 每天 | `{}` |
| `weekly` | 每週指定星期 | `{ "weekdays": [0–6] }`（0=日） |
| `monthly_days` | 每月指定幾號 | `{ "days": [1–31] }` |
| `monthly_weekday` | 每月第 N 個星期幾 | `{ "week": 1–4\|-1, "weekday": 0–6 }`（-1=最後一個） |
| `yearly` | 每年指定月日 | `{ "month": 1–12, "day": 1–31 }` |

編輯彈窗用分段控件切換週期，並展示對應選項（核取方塊／多選日期／第幾個+星期／年曆 MM-DD）。時刻以 **Asia/Hong_Kong** 為準。

### 8.4 調度與手動運行

- `ScheduledJobsRunner` 每分鐘 tick；對 `enabled` 週期任務，在 HK `runTime` **且**符合週期配置的當分鐘觸發一次。
- **手動「運行」與自動調度走同一 handler**（租金任務即 `runDueRentInvoices`）：
  - 僅處理狀態 = **租賃中** 的合約
  - 簽約中等狀態不開票（只計攔截）
  - 無可開票期或未進提前窗 → 開立 0 張，**不破壞業務規則**
- 舊的 `InvoiceBillingScheduler`（小時級）已移除，統一由此框架調度。

### 8.5 執行日誌（`scheduled_job_logs`）

- **按「任務跑了一次」記 1 條**（自動或手動），結果為匯總文案（如「開立 N 張…」）。
- **不是**按合約逐條寫日誌；合約再多，一天自動跑一次也大約只多 1 條（外加手動次數）。
- 列表接口默認返回最近約 50 條；長期可再加清理策略。
- 每次運行同時更新任務的 `lastRun*` / `nextRunAt`。

### 8.6 API

| 方法 | 路徑 | 權限 | 說明 |
|------|------|------|------|
| `GET` | `/scheduled-jobs` | 登入（有菜單即可） | 列表；可選 `scheduleKind` |
| `GET` | `/scheduled-jobs/handlers` | 同上 | 可用處理器目錄 |
| `GET` | `/scheduled-jobs/:id` | 同上 | 詳情 |
| `GET` | `/scheduled-jobs/:id/logs` | 同上 | 最近執行日誌 |
| `PATCH` | `/scheduled-jobs/:id` | `scheduledJobs:update` | 更新名稱／開關／時刻／週期／`recurrenceConfig` |
| `POST` | `/scheduled-jobs/:id/run` | `scheduledJobs:update` | 立即手動運行 |

參考：`ScheduledJobListView.vue`、`backend/src/scheduled-jobs/*`、`permission.catalog` → `scheduledJobs`

## 9. 角色與功能權限

入口：**系統管理 → 角色管理**（功能按鈕權限抽屜；菜單權限另見「菜單」操作）。

### 9.1 角色層級（默認能力）

| 角色 | 功能按鈕權限 | 誰可改該角色的功能權限 |
|------|--------------|------------------------|
| **超級管理員**（`superAdmin`） | **默認擁有目錄內全部**（不依賴綁定表；角色本身無需也不應配置） | 不可配置（界面只讀提示） |
| **管理員**（`admin`） | **不**默認全開；與普通角色一樣讀角色—權限綁定表，須由超級管理員勾選後才有對應按鈕 | **僅超級管理員**可改 |
| **其他角色**（含預置 `user`、自訂角色） | 讀綁定表；預置項由系統啟動同步補齊默認（如可查不可刪） | 有角色更新權限即可；**管理員賦權時僅能勾選自身已有項** |

補充：

- 「系統管理」類菜單是否可見，與功能按鈕是否可點是分開的：即使能進頁面，沒有對應功能碼（如 `scheduledJobs:update`）仍不能改／跑任務。
- 歷史庫若曾給管理員灌過全量綁定，會暫時仍有那些權限，直到超級管理員在角色管理中調整。

### 9.2 管理員為其他角色賦權

| 規則 | 說明 |
|------|------|
| 目錄過濾 | 非超級管理員打開「功能」抽屜時，**只列出自身已有**的權限碼；沒有的項不出現 |
| 保存校驗 | 後端拒絕提交超出操作者自身範圍的碼 |
| 保留不可見項 | 目標角色上已有、但操作者自己沒有的權限，保存時**原樣保留**，避免管理員「清空可見項」時誤刪更高權限 |

超級管理員賦權時看到**全量目錄**，可為管理員及其他角色任意勾選。

### 9.3 功能按鈕發光描邊

| 項目 | 規則 |
|------|------|
| 何時算「獨占」 | 當前**沒有任何非超級管理員角色**（含管理員、普通角色）綁定該功能碼 |
| 誰看得見描邊 | **僅超級管理員**帳號；提示為「僅超級管理員擁有此功能」 |
| 管理員視角 | **不再**因「只有管理員能點」而描邊；管理員已獲授權的按鈕外觀與一般按鈕相同 |

用途：提醒超管「這項還沒下放給任何角色」。一旦授給管理員或其他角色，描邊消失。

### 9.4 與財務刪除等的關係

單刪／批量刪等仍依賴具體功能碼（如 `invoices:delete`）。預設普通角色不含刪除權；是否授權走 §9.1–9.2，**不再**假設「管理員一定有刪除權」。

## 10. 注意事項總表

| 主題 | 注意 |
|------|------|
| 合約總日期與合約期 | 雙向聯動；提交時首段開始 / 末段結束必須對齊總日期 |
| 合約期時長 | 日期與單位/數值雙向；用事件驅動 + 鎖，避免死循環 |
| 多段串聯 | 改中間段會牽動後續段與可能回寫總到期日 |
| 免租期 | 不可僅有免租；前綴免租後移首張租金發票起算日 |
| 創建即開票 | 新增/保存合約即生成按金 + 首期租金發票（及應收）；與是否開單無關 |
| 開單 | 僅簽約中：上傳簽約文件 → 租賃中；其他狀態彈窗提示「當前狀態不可執行該操作」；定金收據於開單時生成 |
| 後續開票 | 日任務僅「租賃中」；簽約中進入第 2 期提前窗只提示、不開票 |
| 合約列表快捷篩選 | 「全部／整租／分租」與「即將到期」可同時使用；即將到期顯示數量；條件預設 30 天、含租賃中／退租中；僅 SuperAdmin 可在芯片旁改條件 |
| 合約列表操作列 | 主列：編輯／收款／列印／…；更多分組為辦理／記錄／結束；頂部顯示合約編號防誤操作；續約／退租暫未上線；取消僅簽約中；刪除需權限並確認 |
| 合約收款 | 列表「收款」→ 彈窗列該合約應收與未收合計；勾選後確認收款日期／方式並為每筆未收應收開立收據；後端按收據合計回寫應收已收／未收 |
| 系統設置 | 「系統管理 → 系統設置」維護自動開票提前天數；即將到期條件在合約列表由 SuperAdmin 調整 |
| 定時任務 | 「系統管理 → 定時任務」開關／手動運行／改時刻與重複週期；不可刪除；日誌按「每次運行」記 1 條；手動與自動同規則；操作需已被授予 `scheduledJobs:update`（管理員不默認全開）；任務碼 `rent_invoice_due` |
| 發票編輯 | 列表編輯前回填詳情；不可改合約；服務細節表 5 行分頁＋拖拽＋雙擊序號 |
| 發票產生方式 | `billingKind` 僅 `manual`／`auto`；類型看 `invoiceType`；列表可篩 |
| 發票描述 | 列表／表單／詳情隱藏；庫與列印數據仍保留；無明細時列印回退用類型或週期文案 |
| 發票彈窗預覽 | 新增／編輯均可；按表單草稿生成 PDF，無需先保存 |
| 短租發票 | 房間須開「允許短租」；`source=short_term` 無合約；租期占房顯示短租中；與合約／其它短租互斥；`billingKind=manual` |
| 操作列配色 | 以合約為準：編輯綠／列印霧紫／刪除紅／收款橙／開單霧藍等（`action-pill--*`） |
| 刪發票 | 會級聯刪應收；收據斷開發票關聯而非必刪收據 |
| 刪除權限 | 預設角色無刪除；需角色管理授權；管理員亦不默認擁有 |
| 功能權限 | 見 §9：僅超管默認全開；管理員由超管配置；管理員賦權僅限自身已有；描邊僅超管獨占時對超管顯示 |
| 關聯抽屜 | 操作在工具列；列印不可批量；刪後刷新主表 |
| 無操作的關聯表 | 先不要多選框 |
| 彈窗內容區全屏 | 業務 `el-dialog` 標題欄有全屏鈕：鋪滿側欄以右的 `.main`（含頂欄快捷與內容區；即側欄展開時紅框工作區）；側欄始終不被遮罩。進度／MessageBox 除外；可加 `lb-dialog--no-content-fs` 排除 |
| Windows 源碼編碼 | 禁止用 PowerShell `Set-Content` 等回寫 UTF-8 源文件（見 `.cursor/rules/utf8-powershell.mdc`） |
| 開發服務 | 改完代碼後不主動重啟前後端；用戶自行刷新 |
| 文檔 | 每次流程/參數變更必須更新本文 |
